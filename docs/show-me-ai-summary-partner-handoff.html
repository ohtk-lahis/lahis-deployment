LAHIS integration · partner handoff

Officer Ask AI

LAHIS does not call your model. An officer clicks Ask AI. You receive a signed webhook, pull report data, then write a staff comment.

What changed

Already live — report.submitted

  • Fires when a report is stored
  • One event per report
  • Thin IDs and links only

New — ai.evaluation_requested

  • Fires when an officer clicks Ask AI
  • Optional userPrompt
  • Many requests per report (60s wait)
  • Pull rendered text, comments, images
  • Write comment with metadata.kind=summary

Runtime flow

1
Officer · dashboard
Clicks Ask AI. Optional extra instruction. Mutation returns at once.
2
LAHIS
HMAC POST ai.evaluation_requested to your webhook. Thin body + pull links.
3
Your receiver
Verify signature. Return 2xx. Queue the model job. Do not wait on the webhook.
4
Your service
OAuth token. GET incident (renderer text), GET comments, GET images if approved.
5
Your service
POST comment metadata.kind=summary, key ai-summary:{eventId}.
6
Officer
Summary appears in Comments. Excel suspected-disease is not overwritten.

Subscribe this event

An endpoint that only lists report.submitted will not receive officer clicks.

ScopeWhy
ai:read_reportWebhook delivery + GET comments + extra incident text
incident:readGET incident detail
ai:read_imagesPhotos, only if vision is approved
ai:create_commentWrite the summary

HMAC is the same as report.submitted: POST + "\\n" + path + "\\n" + timestamp + "\\n" + raw body.

Webhook body

userPrompt is omitted when the officer leaves Extra instruction empty. Do not treat "" as a prompt.

{
  "schemaVersion": "2026-08-31",
  "eventType": "ai.evaluation_requested",
  "eventId": "44444444-4444-4444-4444-444444444444",
  "purpose": "summary",
  "userPrompt": "Focus on clinical signs and deaths.",
  "requestedBy": { "id": "10", "username": "L01", "role": "ADM" },
  "report": { "id": "22222222-2222-2222-2222-222222222222" },
  "links": {
    "incident": "/api/integrations/v1/incidents/{id}",
    "comments": "/api/integrations/v1/reports/{id}/comments",
    "images": "/api/integrations/v1/reports/{id}/images"
  }
}

Pull, then write

GET incident (needs both read scopes)

List stays thin. Detail adds these fields only with ai:read_report.

{
  "village": { "id": 10, "code": "V-1", "name": "Sangthong" },
  "rendererData": "staff-visible report text",
  "followUps": [{ "id": "…", "rendererData": "…" }]
}

Also GET comments and images. Comment GET returns thread text, not file bytes.

POST comment

Idempotency-Key: ai-summary:{eventId}

{
  "externalActionId": "ai-summary-{eventId}",
  "body": "AI summary:\\n…",
  "visibility": "staff",
  "metadata": {
    "kind": "summary",
    "requestedEventId": "{eventId}"
  }
}

kind=summary keeps Excel ai_suspected unchanged. Missing kind copies the body into suspected disease.

Partner checklist

  • Webhook event types include ai.evaluation_requested
  • Verify HMAC, tenant, event ID, then 2xx quickly
  • If userPrompt is present, add it on top of the default summarize task
  • Pull renderer text, comments, and approved images
  • Write staff comment with metadata.kind=summary
  • Do not call GraphQL or scrape dashboard media URLs
